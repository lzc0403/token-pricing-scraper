## 飞书播报来源可读性改造（用户反馈：[tencent] 无法分辨站点）

### 问题
- 播报里 `DeepSeek V4 Flash［tencent］` 用内部 source ID，看不出是腾讯云CN / 腾讯云国际 / 原厂直供 / 自建。
- 连带发现 store.py 对比 bug：同一 (canonical, source) 下多行不同计费口径（原厂直供闲时/高峰、自建）互相覆盖，对比错位。

### 修复
1. **core/store.py** `compare_previous`：
   - prev_idx key 从 `(canonical, source)` → `(canonical, source, condition or "")`，用 pop 消费防重复匹配。
   - deltas 增加 `condition` 字段。
2. **core/notifier.py**：
   - 新增 `SOURCE_LABELS`（与站点页一致：tencent→腾讯云国际、tencent_cn→腾讯云CN 等）。
   - 新增 `_condition_label`（空闲时段|原厂直供→原厂直供·闲时价；高峰时段|原厂直供→原厂直供·高峰价等，未识别原文展示）。
   - `_group_key` 加入 condition；`_src_display` 输出「站点名·口径」如「腾讯云国际·原厂直供·高峰价」。
3. **tests/test_notifier.py**：断言改中文来源名，新增 test_build_message_condition_display。13 例全过。

### 教训
- condition 原文格式是 `"空闲时段 | 原厂直供"`（带空格竖线），映射表 key 必须完全一致。
- f-string 里 `.lstrip("· ")` 写法易出双点号 bug，拼接逻辑保持简单。

## 播报模板精简+表格化（用户反馈：文案要精简、要表格样式）

### 方案选择
- 飞书自定义机器人真表格只有 interactive 卡片（新卡片 2.0），但 webhook 关键词校验对非 text 类型有风险（此前 msg_type=markdown 已踩坑 19024 两轮）——选 text 内伪表格：`模型｜来源｜入 $x→$y ↑z%`，每行一条，按幅度降序。

### 实现（commit `6b5114c`）
1. **core/notifier.py**：
   - 消息结构：标题 → 概览一行 → 表格区 → 💡提醒单行 → 链接+关键词。删除【重点/其他】分区、MAJOR_PCT、最大变动行、免责声明。
   - `_table_rows()`：每行 `模型｜站点·口径｜入 旧→新 ↑%  出 旧→新 ↓%`；字段缩写入/出，箭头 ↑↓ 替代 ⬆️⬇️。
   - 口径标签缩短：`原厂直供·闲时价`→`原厂·闲时`、`腾讯云自建`→`自建`、`阿里云自部署`→`自部署`。
2. **tests/test_notifier.py**：重写断言（test_build_message_table_layout 验证排序+行格式），13 例全过。

### 效果
20 处变动从 ~40 行压缩到 17 行 / 644 字符。
