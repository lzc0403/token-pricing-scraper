## 修复阿里云国际站 DeepSeek 输入价缺失 + 腾讯云缓存价错填

**问题**（用户截图反馈）：
1. 阿里云国际站 DeepSeek V4 Pro/Flash 输入价显示 `— USD`
2. 腾讯云 DeepSeek V4 Flash 缓存命中价显示 `0.28`（应为 0.028）

**根因**：阿里云国际站 Model Studio 定价页有**两张表**：
- TABLE 0（无 Time Period 列）：DeepSeek 等转售模型 Input Price 列为 `-`，导致 CSV 解析输入价缺失
- TABLE 1（含 Time Period 列）：DeepSeek 带 `-0731`/`-0813` 后缀，列序整体右移一位（Time Period 占第 4 列），含完整峰谷价（Off-peak/Peak）

旧 `scrapers/aliyun_intl.py` 只解析 TABLE 0（列序硬编码 3/4/5），DeepSeek 输入价为 None，缓存价也错（TABLE 0 的 Implicit Cache Hit 对 DeepSeek 是 `-`，而 `$2.4/$4.8` 是输出/输入位置错位导致 cache=4.8 异常）。

**修复**（commit `ebf4b37`，已 push）：
- 自动检测表头 `Time Period` → 峰谷表列序 (4,5,6)，普通表 (3,4,5)
- 同一 norm 的 Off-peak/Peak 双行合并为单行，附加 peak_* 6 字段，condition 增加「峰谷计费」
- 去重优先保留有输入价、来自峰谷表、无后缀基准名的记录

**结果**：
- 阿里云国际 DeepSeek V4 Pro: 高 1.32 / 闲 0.66 USD，缓存 0.132
- 阿里云国际 DeepSeek V4 Flash: 高 0.44 / 闲 0.22 USD，缓存 0.044
- 腾讯云 DeepSeek V4 Flash 缓存恢复 0.028（2148 行验证）

**经验**：SPA 控制台页面改版常把表格拆成多张（普通表 + 峰谷表），scraper 不能只认第一张表，需按表头特征（Time Period/Peak 列）自动分流列序。
