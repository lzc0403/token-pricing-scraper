旧结论

本次实测

根因判定
抽查 openrouter.py:217（float 与 None 比较）与 tencent.py:107/124（索引可能为 None）——均被运行时逻辑守卫保护（如行 105 的长度检查、逻辑互锁），属类型注解债而非运行时 bug。当前不影响数据正确性，但会随 mypy 版本升级在未纳入 CI 范围时静默膨胀。
旧 「OpenAI 长上下文动态抓取」——应为永久不可行
旧结论
v1 表述
中期 #5 标记为「暂缓」（treated as temporary deferral）。
新证据
调研结论
OpenAI 定价页使用 Astro 预渲染，真实页面 TextTokenPricingTables 的 props 每行仅 4 列（短文本档），长文本档由前端 JS 在运行时注入 DOM，静态抓取（requests + parsel）根本拿不到。强行用 Playwright 读 DOM 成本高且极易因页面改版脆断。
更正后
正确表述
应从「暂缓」改为「永久不可行（hardcoded by design）」。当前硬编码值（sol 10/45、terra 4/18、luna 0.4/1.8）经核与官网真实长档价一致，未过期；靠 audit 的 OPENAI_LONG_DEV 交叉校验兜底即可。**不应再投入尝试动态抓取**，而是把硬编码显式标注为「预期的、受交叉校验保护的常量」。
旧 硬编码定价风险未突出为独立风险项
旧结论
v1 表述
只把 _LONG_CONTEXT_PRICES 当背景提及，未系统盘点所有硬编码价格常量。
新证据
本次盘点
项目存在多处硬编码价格常量，应统一标为「数据真实来源风险」：
  • scrapers/openai.py · _LONG_CONTEXT_PRICES —— GPT-5.6 Sol/Terra/Luna 长文本价（已知）
  • scrapers/base.py / 其他 · 价格兜底值
  • config/mainstream_models.yml —— 目录静态价由 _hydrate_catalog_prices() 用 live 官网价覆盖，但若无对应源则回落到目录静态价（潜在陈旧风险）
更正后
建议
在报告中新增「数据真实性」风险条目，集中列出所有硬编码价格来源、兜底逻辑，并给出「交叉校验 + 过期检测」的统一策略。
